# Moving to the 3.0 candidate

Import `QuickChick` and use `QCDerive` for derivations. Generator, enumerator,
and checker commands now use the scheduled engine and register typeclass
instances. The familiar command forms remain available:

```coq
From QuickChick Require Import QuickChick.
Inductive box (A : Type) := Box : A -> box A.
QCDerive (GenSized, EnumSized) for box.
```

These commands leave the generated dictionaries available to ordinary
typeclass search. Type and class arguments are implicit; value inputs remain
explicit. Dependencies carry their full type arguments, so a requirement for
`Enum (list A)` is not reduced to one for `Enum A`.

The bare `Derive` spelling is opt-in because it can conflict with Stdlib and
other plugins:

```coq
From QuickChick Require Import LegacyDerive.
Derive GenSized for box.
```

This import changes the spelling only: bare `Derive` still selects the new
dispatcher. To select the old engine explicitly, use `QCDeriveLegacy` or
`DeriveLegacy`. Both issue a deprecation warning. They are useful for old
derivations whose fixed or repeated inputs, reordered outputs, or proof
automation expect the old generated terms. There is no silent fallback when
the scheduled engine rejects a command.

For a predicate, put output variables in the lambda passed to `Generator` or
`Enumerator`. The output must occur once as a whole predicate argument;
implicit type arguments are not outputs:

```coq
Inductive related {A B : Type} : A -> B -> Prop :=
| Related : forall x y, related x y.
QCDerive Checker for (@related A B x y).
QCDerive Generator for (fun (y : B) => @related A B x y).
```

`quickchick` inside a proof prepares and runs a temporary test of the current
goal. It leaves a local function, normally named `theorem`, that you can rerun
with `QuickChick (theorem size)` or `QuickChickWith`. The test and any derived
helpers disappear after `Qed`, `Defined`, or `Abort`. Explicit derivation
commands remain persistent. Testing does not close the goal or prove it.
See the compiled [proof-scoped example](../tutorials/ProofScopedTests.v).

Automatic testing uses suitable instances already in scope and derives missing
ones for its own test. An existing declaration name alone does not count as an
instance. Explicit derivations can be repeated; a later declaration receives
a fresh name. Source code that refers to generated helper names or supplies
their implicit arguments explicitly may need adjustment; prefer resolving the
class interface where possible.

The scheduled engine currently rejects fixed or repeated term inputs and
reordered outputs in public derivation commands. It also cannot schedule some
constructor applications. Use the explicit legacy command where it supports
the old form. For the exact command table and tested limits, see
[DerivationDispatch.md](DerivationDispatch.md). Scoring-policy and weighting
experiments have no public setting yet; existing flags and defaults remain in
effect.

The commands above are compiled in [MigrationExamples.v](MigrationExamples.v).
